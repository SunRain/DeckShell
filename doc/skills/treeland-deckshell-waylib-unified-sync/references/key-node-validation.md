# 关键节点分段验收

## 两种粒度

逐提交同步不等于逐提交构建。每个来源提交仍执行 R→C→P、内容投影、来源追溯、两层 gitlink 和 C 源码合同检查；普通中间提交不承诺可编译。完整构建、安装合同和消费测试只在预先选定的关键节点执行，必需的 C/R 基线验证仍保留。

本 skill 复用现有单区间流程：每段的 `range_head` 就是一个必验节点。不增加调度器，不自动遍历或构建全部 tag，也不把单次整段报告解释成所有中间 tag 已通过。

## 冻结节点

执行前在已有 `refs_doc` 中记录整体 `(base..head]`、冻结的 `source_tip`、所选节点的 ref/完整 commit SHA，以及每段证据目录：

- 仅使用调用者选定的发布 tag 或明确 SHA，不猜最近 tag，不按名称或日期替代 Git 祖先顺序。
- tag 使用 `git -C "$SOURCE_REPO" rev-parse "$NODE_REF^{commit}"` 剥离为提交；确认 `base < node <= head <= source_tip`，相邻节点有祖先关系。对象必须已在本地，不能隐式 fetch。
- 整体 `head` 始终是最后一个必验节点，即使它不是 tag。多个名称指向同一 SHA 时共用一次节点验收；左端 `base` 不作为本段新增节点。
- 将相邻节点构造成连续、不重叠的左开右闭区间。预检全部分段；任何 merge、unknown 或未批准路径仍阻断。按 tag 切段不能绕过 [首次 subtree 导入边界](unified-contract.md#首次-subtree-导入边界)。

例如整体 `(A..Z]` 选定 tag `T` 和终点 `Z`，则实际调用两次：

| 分段 | 来源范围 | 必验快照 |
|---|---|---|
| 1 | `(A..T]` | T 对应的目标 P/C/R 候选 |
| 2 | `(T..Z]` | Z 对应的目标 P/C/R 候选 |

上游 tag 存在或上游 CI 通过，不证明目标 DeckShell 与其匹配的 C/R 已通过构建。节点恰好未生成某层新提交时，该层使用 manifest 中延续的真实 SHA，不伪造节点提交。

## 每段执行和接续

1. 按 SKILL.md 冻结本段来源及 P/C/R 基线，使用独立 run-id、证据目录和 linked worktree，执行本段 inventory、逐提交 replay 和结构化验证。
2. 从本段 manifest 物化候选依赖，完成 C/R 必需基线与候选验证、P 候选构建、安装合同、固定 namespace 探针及消费测试。不得复用上一段 build/install 目录或借用它的 PASS。
3. 必需 CMake 构建 ID 只接受 `cmake --build "$BUILD"` 的默认完整构建。允许并行数、配置、详细输出和 `--clean-first`；拒绝 `--target`/`-t`（包括 all/help）、原生 `-- ...` 参数、空跑和其他构建模式。诊断性局部构建可使用非必需 ID，但不满足验收。
   本段 P 候选包含依赖 DConfig 的协议测试时，运行 CTest 前按 [隔离运行方案](protocol-test-runtime.md) 准备并记录本段运行依赖；不安装系统服务，不借用历史节点的测试结果，也不把依赖缺失转为跳过。
4. 生成本段完整报告。缺证据或任一必需构建/测试/合同失败时停止；不能越过失败节点去下一个 tag，再用后续成功抵消。
5. 完整报告通过且授权覆盖本段后，执行既有 R→C→P expected-old closeout。授权可以预先覆盖明确列出的整组分段和目标 refs；不要重复索取已覆盖的授权。未获收口授权时停在“本段验收完成、尚未收口”，不能声明整组同步完成。
6. 后段以**前段已完成收口的** P/C/R 目标 SHA 为基线，R target ref 必须实际指向新的 R base。新建该段 worktree、journal、build/install 和报告；不修改上一段 manifest，不把最后一段报告用于从最初基线跨段收口。

这是分段收口，不是跨整组节点的原子事务。后段失败时保留前段已验收的 refs 和本段现场；partial closeout 仍按原有 journal 恢复，不回滚已更新的下层 refs。

默认完整构建使用项目正常产品配置，不能通过关闭必需产品目标来制造成功。源码合同保持、C/P 实际使用 R、内容等价及 gitlink 校验都不因构建频率放宽而撤销；需要公共迁移时必须有独立的明确授权和 [精确迁移审批](evidence-schema.md#显式公共合同迁移)，不能把节点分段当作豁免。

## 报告口径

每段 `sync-report.json` 的 `build_scope` 固定为 `range-head-only` 并绑定该段来源终点；三仓实际候选仍由 `final_*_head` 标识。普通中间提交标为“不要求构建”，不是构建通过；没有独立段末证据的 tag 不能列为已验收。

在 `refs_doc` 的冻结节点表中链接各段 manifest、验证记录和完整报告。只有清单中的每个节点均有对应 PASS、分段和 P/C/R 基线连续、且获准的分段收口完成，才能声明整组本地同步完成。最后一段 PASS 只证明最后一段，不能代替其他节点证据。

旧报告、旧字面 pkg-config 快照或允许局部目标的构建记录须用当前工具重新验证和生成；不得补写字段或沿用旧 PASS。
